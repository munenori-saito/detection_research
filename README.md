# 逆走車検知手法研究：今後やるべきこと

## 1. 目的と要件の明確化

- 対象とする道路・区間・方向を決める（高速道路本線、IC流入部、一般道、トンネル、駐車場など）。
- 検知対象を定義する（乗用車、大型車、二輪車、工事車両、後退車両、歩行者・動物などを含めるか）。
- 「逆走」とみなす条件を決める。例：進行方向の反対走行、一定距離以上の継続走行、複数フレームでの確認、複数センサでの一致など。
- 必要な検知距離、警報までの許容遅延、検知率、誤検知率、夜間・悪天候時の性能目標を設定する。
- 検知後の対応を決める（警報、標識、管理者通知、自動制御、録画保存など）。

## 2. 検出方法の選定

### 検討すべき手法

- カメラ＋画像認識：車両検出、追跡、進行方向推定、軌跡解析。
- レーダー：夜間・悪天候に強く、速度・距離・方向の計測に向く。
- ループコイル・磁気センサ：設置箇所は限られるが、比較的安定した検知が可能。
- V2X・車載通信：車両側の情報を利用できる場合に有効。
- GPS・プローブデータ：広域監視や事後分析に有効だが、リアルタイム性に課題がある可能性。
- 複数センサ融合：カメラ＋レーダーなどで、精度と頑健性を高める。

### 選定時の比較項目

| 観点 | 確認事項 |
|---|---|
| 検知性能 | 検知率、誤検知率、見逃し率、警報遅延 |
| 環境耐性 | 夜間、逆光、雨、霧、汚れ、遮蔽、速度変化 |
| 設置性 | 既設インフラとの適合性、電源、通信、設置位置 |
| コスト | 機器費、施工費、保守費、演算コスト |
| 運用性 | 警報の信頼性、誤報対応、保守・点検の負担 |
| プライバシー | 個人識別情報の取り扱い、映像保存期間、アクセス制御 |

## 3. データセットの整備

- 正例データ：実際の逆走イベント、逆走に近い走行軌跡、模擬逆走データなど。
- 負例データ：正常走行、Uターン、工事車両の後退、停止車両、歩行者、動物、影、映像ブレなど。
- データ収集条件：昼／夜、晴天／雨、異なる速度、交通量、遮蔽の有無、カメラ角度・設置高さ。
- アノテーション方針：車両ID、位置、速度、進行方向、逆走開始・終了時刻、誤検知原因などを記録する。
- データ分割：学習用、検証用、テスト用を分け、同じイベントや同じ日時のデータが両方に混在しないようにする。
- データ不足への対応：実車実験、シミュレーション、映像合成、過去事例の再利用などを検討する。

## 4. アルゴリズム設計

- 車両検出：対象車両を画像またはセンサデータから検出する。
- 追跡：同一車両を連続的に追跡し、IDの切替や重複検出を抑制する。
- 進行方向推定：車両の移動ベクトル、車頭方向、車線情報などから進行方向を判定する。
- 軌跡解析：一定区間での継続走行、速度、位置変化を確認する。
- 誤検知除去：後退、Uターン、一時停止、工事車両、歩行者、影などを除外する。
- 警報判定：検知確度、継続時間、進入区域、速度などを組み合わせて警報を出す。
- ログ記録：検知時刻、位置、映像、判定根拠、警報履歴を保存する。

## 5. 性能評価方法の選定

### 評価単位

- フレーム単位だけでなく、逆走イベント単位で評価する。
- 同一の逆走イベントを正しく検知・追跡できたかを確認する。
- 警報の発生時刻、位置、対象車両IDを正解データと照合する。

### 主要指標

| 指標 | 定義 |
|---|---|
| 検知率／再現率 | 実際の逆走イベントのうち、正しく検知できた割合 |
| 誤検知率 | 逆走でない事象を逆走と判断した割合 |
| 見逃し率 | 逆走イベントを見逃した割合 |
| 適合率 | 警報のうち、実際に逆走だった割合 |
| 応答遅延 | 逆走開始から検知・警報までの時間 |
| 追跡性能 | 同一車両を連続して追跡できるか、ID切替の少なさ |
| リアルタイム性 | 処理遅延、FPS、エッジ装置での稼働可否 |
| ロバスト性 | 夜間・悪天候・遮蔽・速度変化時の性能低下の程度 |

### 合格基準の設定

- 検知率、誤検知率、見逃し率について、目標値を事前に設定する。
- 例として、検知率90%以上、誤検知率10%未満などの基準を参考にする。
- 夜間・雨天・低照度など、条件別に目標値を設定する。
- 誤検知よりも見逃しを重視するか、運用コストを重視するか、優先順位を明確にする。

## 6. 実証実験計画

- 実験場所：実道路、閉鎖区間、テストコース、シミュレーション環境など。
- 実験条件：昼／夜、晴天／雨、異なる速度、複数台同時走行、遮蔽あり、工事車両の後退など。
- 評価方法：制御実験と実運用に近い無制御実験を組み合わせる。
- 比較対象：既存手法、単純なルールベース手法、提案手法の比較。
- 繰り返し回数：統計的な信頼性を確保するため、十分な試行回数を設定する。
- 記録項目：映像、センサデータ、警報履歴、正解ラベル、環境条件、障害情報。

## 7. 誤検知・見逃しの原因分析

- 誤検知の原因を分類する（後退、Uターン、工事車両、歩行者、影、映像ブレなど）。
- 見逃しの原因を分類する（夜間、逆光、遮蔽、速度、検知エリア外など）。
- 検知閾値、カメラ角度、速度設定、対象物設定などの調整方針を決める。
- 改善後の再評価を行い、改善効果を定量的に確認する。

## 8. 運用設計

- 警報先：管制室、管理者、自動制御システムなど。
- 通知内容：発生時刻、位置、車両情報、映像、緊急度。
- 誤報時の対応：オペレータ確認、再確認、警報解除の手順。
- 保守点検：カメラ清掃、レンズ汚れ、センサ異常、通信障害の確認。
- ログ保存：検知履歴、警報履歴、誤検知履歴の保存期間とアクセス制御。
- プライバシー対応：個人識別情報の取り扱い、映像保存期間、アクセス制御。

## 9. 研究の進め方

1. 対象シーンと要件を決める。
2. 検知原理・センサ構成の候補を絞る。
3. データ収集・アノテーション計画を作る。
4. ベースライン手法を実装する。
5. オフライン評価で検知率・誤検知率・遅延を測る。
6. 失敗ケースを分析し、閾値・追跡・フィルタを改善する。
7. 実証環境で昼夜・速度・遮蔽条件を変えて再評価する。
8. 警報運用、保守、コスト、安全性を含めて総合評価する。

## 10. 重要な盲点

- 正解データの質が評価結果を左右する。
- フレーム単位の評価では、追跡の長さだけが評価される可能性がある。
- 誤検知の原因分析を怠ると、改善が難しくなる。
- 比較対象がないと、提案手法の優位性を示せない。
- 再現性と文書化を怠ると、論文化・特許化・実装移行が難しくなる。
